# 状态机模块需求说明（MVP）

## 1. 模块定位

状态机模块用于监测系统内外部业务事件，并根据规则自动执行对应动作（skill）。第一版重点服务项目与运输任务流程，不替代人工操作，只做事件记录、规则匹配和基础通知。

未来可扩展为自动监测企业微信群、WhatsApp 群、GPS 轨迹、司机打卡、财务状态等信息，并自动更新任务状态或触发提醒。

## 2. 一期目标

1. 支持配置状态机规则。
2. 支持记录状态机事件。
3. 支持记录规则执行日志。
4. 接入运输任务流程节点动作事件。
5. 支持基础 skill：记录日志、飞书卡片提醒。
6. 为后续外部消息采集、AI 分析和自动状态更新预留接口。

## 3. 业务对象

### 状态机规则

字段：

- 规则名称
- 监听范围：流程节点、运输任务、外部消息、GPS、财务、全部
- 事件类型：节点开始、节点完成、节点异常、节点退回、节点挂起、节点待处理等
- 条件 JSON：用于后续配置国家、节点、客户、项目、超时等条件
- 动作类型：仅记录、飞书卡片、待办催办
- 动作配置 JSON：用于配置通知对象、模板、跳转地址等
- 启用状态
- 备注

### 状态机事件

字段：

- 来源：workflow、gps、wechat、whatsapp、system
- 监听范围
- 事件类型
- 关联对象 ID
- 事件载荷 JSON
- 状态：pending、processed、failed
- 创建时间、处理时间

### 执行日志

字段：

- 规则 ID
- 事件 ID
- 动作类型
- 执行状态
- 执行结果
- 创建时间

## 4. 一期事件

流程节点动作产生以下事件：

- `workflow.node.started`
- `workflow.node.saved`
- `workflow.node.completed`
- `workflow.node.returned`
- `workflow.node.skipped`
- `workflow.node.held`
- `workflow.node.exception`
- `workflow.node.reassigned`
- `workflow.node.waiting`

## 5. 一期 skill

### log_only

只记录匹配日志，不改变业务数据。

### feishu_card

对流程节点关联负责人或角色发送飞书卡片。第一版复用现有流程节点催办逻辑。

### todo_reminder

作为后续待办提醒 skill 预留，第一版记录日志，不主动重复生成待办。

## 6. 后续版本

第二版可考虑：

1. 外部消息接入：企业微信群、WhatsApp 群、Telegram 群。
2. AI 内容识别：自动抽取任务号、车牌、位置、异常、预计到达时间。
3. 自动更新任务状态：根据可信事件更新节点记录或轨迹记录。
4. 定时监测：超时、GPS 长时间未更新、节点长期未处理。
5. 重试机制：通知失败自动重试。
6. 规则版本管理：每次规则调整保留历史版本。
7. 可视化编排：用流程图配置状态机与 skill。

## 7. MVP 边界

第一版不做自动改状态、不做外部群消息监听、不做复杂条件表达式引擎。所有自动动作都以记录和提醒为主，避免误操作影响真实业务流程。
